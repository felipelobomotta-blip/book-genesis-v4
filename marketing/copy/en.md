## LinkedIn founder post

I built Book Genesis 5 — Imagination Edition because “write me a book” is the least interesting use of AI.

The interesting work begins after the first draft: a premise gets clearer, an outline exposes weak choices, a chapter survives a blind editorial read, and a manuscript can be stopped when its ending fails the promise of its opening.

Book Genesis is an open-source writing runner for that work. You start with an idea and choose the model setup. It creates a project you can inspect: brief, outline, chapter attempts, model-reader feedback, manuscript audit, local reading report, and Markdown or EPUB export.

This is a beta, so I tested it like one. 279 automated tests passed locally on Windows/Python 3.11 before remote CI. One real-provider smoke run created a 1,910-word Portuguese story. An early internal reader signal looked excellent. Then the full-prose audit found a structural failure and returned MAJOR REWRITE.

That finding changed the code. The audit now blocks the workflow instead of letting a manuscript look complete because a report exists.

I do not think software can promise a bestseller, replace editors, or decide whether a book is ready to publish. I do think creators deserve a process they can inspect, question, pause, and improve.

Creativity is the starting point. The story is yours.

Try one chapter. Report what fails. Contribute where the writing process can become more truthful and useful.

## Show HN

**Title:** Show HN: Book Genesis 5 – a writing runner with a semantic audit gate

**Body:**

I built Book Genesis 5 — Imagination Edition, an MIT-licensed Python CLI for turning one idea into a durable writing project. It orchestrates brief/outline creation, chapter attempts, blind model-reader comparisons, a manuscript audit, local review, and Markdown/EPUB export.

The technical detail I care about is failure handling. Earlier, the presence of an audit report could make a project appear complete even when the audit asked for a rewrite. In this beta, `audit_status: revise` and `major_rewrite` preserve the report, leave the project in `awaiting_revision`, and stop Score and Package. The runner also journals artifact publication and keeps canonical-text history linked by hashes.

Local verification: 279 tests passed on Windows/Python 3.11 before remote CI. A limited real-provider smoke run wrote a 1,910-word Portuguese story; its full-prose audit returned MAJOR REWRITE, which became the regression case for this gate.

I am looking for technical feedback on the state model, provider adapters, recovery behavior, and what evidence would make this useful for authors. It does not claim human-reader validation or bestseller prediction.

Code and documentation: https://github.com/felipelobomotta-blip/book-genesis-v4
